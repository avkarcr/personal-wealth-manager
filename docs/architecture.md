# Архитектура и план перехода

Приложение переводится на модульный монолит с hexagonal-архитектурой по одному законченному сценарию. Flask, существующая схема SQLite и формат invest.enc сохраняются на первом этапе.

## Реализовано

- `wealth_manager/modules/accounts/domain.py`: Account, Purchase, проверки значений.
- `modules/accounts/application.py`: SaveAccount, включая покупку недвижимости и снимок стоимости.
- `modules/accounts/ports.py`: интерфейсы репозитория и UnitOfWork.
- `modules/preferences/application.py`: ChangeLanguage и порты настроек.
- `adapters/persistence/sqlite.py`: реализации портов для существующей схемы.
- `adapters/persistence/unit_of_work.py`: одна операция записи с восстановлением памяти при ошибке; успех возвращается после сохранения зашифрованного файла.
- `bootstrap.py`: сборка сценариев, хранилища и runtime.
- `factory.py`: `create_app(config=None, *, vault=None)`, независимый экземпляр Flask.
- `adapters/runtime.py`: явные `start()` / `close()`, остановка и ожидание фонового потока.
- `adapters/web/security.py`: блокировка соединения на время запроса, guard, legacy-сохранение и освобождение блокировки.
- `adapters/web/legacy_routes.py`: регистрация существующих обработчиков с зависимостями конкретного экземпляра; оставшиеся чтения, настройки и внешние интеграции пока legacy.
- `adapters/web/i18n.py`, `locales/en.json`: переводы интерфейса; русский — исходный язык, английский — каталог.
- «Настройки → Общие»: выбор языка, сохраняемый в зашифрованной базе. Смена языка не меняет названия, заметки и значения существующих классификаторов.

Зависимости: входной HTTP-адаптер → application → domain/порты. Исходящие адаптеры реализуют порты; bootstrap связывает реализации. В ядре нет Flask, SQLite и Vault.

Пакет находится рядом с app.py, чтобы сохранить запуск `python app.py` без установки пакета. Фабрика приложения уже реализована; переход к src-layout пока не выполнялся.

## Этап 1: завершённый каркас приложения

`app.py` — точка входа и экспорт фабрики. Импорт не создаёт Flask/Vault и не запускает поток. `db.py` содержит только схему и миграции, без глобального соединения, `set_vault` и путей из окружения. Каждый экземпляр получает отдельные Vault, сценарии, ключ сессии и runtime в `app.extensions["wealth_manager"]`.

Параметры фабрики: `VAULT_PATH`, `LEGACY_DB_PATH`, `IDLE_MINUTES`, `AUTOLOCK_POLL_SECONDS`, стандартные Flask-параметры. Переменные окружения `INVEST_VAULT`, `INVEST_DB`, `INVEST_IDLE_MIN` читаются при создании приложения; явная конфигурация имеет приоритет. Объект Vault можно передать в фабрику для тестирования адаптера.

Фабрика не открывает хранилище и не запускает фон. `runtime.start()` явно запускает единственный поток автоблокировки; повторный вызов безопасен. `runtime.close()` выставляет Event остановки, ожидает поток, сохраняет и закрывает Vault; повторное закрытие безопасно. После успешного закрытия runtime повторно не запускается, запросы получают 503. При сбое записи ошибка передаётся владельцу, база остаётся доступной для повторного сохранения. Владелец вызывает close вне HTTP-запроса, чтобы не ждать поток, удерживая нужную ему блокировку.

`python app.py` управляет runtime через try/finally и отключает reloader. При использовании фабрики другим сервером жизненным циклом управляет этот сервер/его обёртка. Без явного start сохраняется проверка таймаута на защищённых HTTP-запросах, но нет фоновой блокировки в отсутствие запросов.

Локализация выбирает язык и предоставляет переводы. Синхронизация запросов находится только в security.py. Обработчики регистрируются заново для каждого экземпляра и замыкают только его зависимости. Существующие URL и названия endpoints сохранены.

## Этап 2: операции и чистые расчёты

Завершён. `adapters/web/commands.py` разбирает формы и вызывает сценарии; SQL и сохранение файла находятся за портами. Существующие URL, endpoints, форма базы и RU/EN сохранены.

- `modules/accounts/commands.py`: оценка, архивирование, удаление счёта, историческая стоимость.
- `modules/positions`: позиции, нормализация денежных позиций, ручное и пакетное обновление цен.
- `modules/cashflows`: ручные операции, получение дохода, защита операций, принадлежащих арендному платежу.
- `modules/rentals`: договоры, расписание, статусы платежей и синхронизация доходов. Платёж, доход и снимок сохраняются одним UoW. Редактирование договора обновляет источник и счёт связанных доходов; сокращение договора удаляет будущие ожидаемые платежи и обрезает пересекающиеся периоды без создания периода с концом раньше начала.
- `modules/valuation/domain.py`: чистые курсы/конвертация, XIRR и метрики счёта; `modules/rentals/metrics.py`: просрочка, курсовая разница, занятость недвижимости. Дата расчёта передаётся явно.
- `shared/ports.py`: контракты операций; `adapters/persistence/operations.py`: SQLite-реализации. `bootstrap.build_services(..., today=...)` позволяет задавать часы сценариев в тестах.

`calc.py` сохраняет совместимый API: загружает данные для расчётов и передаёт их чистому ядру. Агрегирование отчётов и внешние поставщики остаются на этапе 3. Получение котировок пока legacy, но запись цен уже выполняется через сценарий позиций. Миграция REAL на Decimal не входит в этап 2.

Некорректные даты, статусы и нечисловые значения NaN/Infinity отклоняются. Обращение к отсутствующей изменяемой сущности возвращает 404; нарушение формата — 400. Исторический разбор текстовых числовых полей с заменой непарсящегося текста на ноль пока сохранён. Пакет цен ограничен указанным счётом, чужие/отсутствующие позиции игнорируются как прежде.

## Транзакции и ограничения переходного этапа

Все перенесённые операции со счетами, позициями, денежными потоками, арендой и смена языка используют VaultUnitOfWork. Под блокировкой хранилища создаётся резервная копия SQLite **в памяти**. При исключении восстанавливается исходная база. Запись покупки и снимка стоимости входит в тот же сценарий. Незашифрованных временных файлов не создаётся.

Все HTTP-запросы удерживают RLock хранилища до teardown, включая сохранение в after_request: это защищает общее SQLite-соединение от автоблокировки и одновременных запросов. Новые сценарии повторно используют тот же RLock. Для локального приложения сериализация запросов приемлема; длительный сетевой запрос временно откладывает автоблокировку.

Настройки курсов, внешние интеграции и чтения пока остаются legacy и используют after_request. Переносимые сценарии обязаны использовать UoW; нельзя начинать его внутри уже открытой транзакции. `calc.take_snapshot(..., commit=False)` — временный адаптер к старым расчётам. Открытие старого дашборда пока по-прежнему создаёт снимок.

Account использует Decimal на входе, но SQLite-адаптер преобразует суммы в REAL для совместимости. Это **не завершённая миграция денежной точности**: переход всей схемы на Decimal/text требует отдельной миграции и проверки расчётов.

## Целевая навигация

1. Дашборд — reporting, агрегированные данные без собственной копии активов.
2. Макроэкономика — определения показателей, значения за период, дата публикации и источник; интерпретация цикла отдельно.
3. Портфели — состав, доходность, распределение позиций, одна обязательная цель на портфель.
4. Активы — инструменты, недвижимость, позиции и оценки.
5. Компании — эмитенты, список наблюдения, отчётность и заметки; компания может существовать без принадлежащих пользователю бумаг.
6. Доходы — работа, фриланс, инвестиционные поступления и аренда.
7. Налоги — события, расчёты по периоду/юрисдикции, уплаты, вычеты и документы.
8. Настройки — Общие (язык и предпочтения профиля), Счета, Цели, Данные и безопасность.

Эти новые бизнес-разделы описаны как целевая модель; пустые страницы и фиктивные функции в текущий интерфейс не добавляются.

## Локализация

Шаблоны используют `_('Исходный текст')`; JavaScript получает каталог через безопасный `tojson`. Английские подписи для asset_class не меняют передаваемые русскоязычные legacy-значения. Для нового языка нужны каталог, добавление к поддерживаемым языкам и пункт выбора. В заблокированном приложении используется язык текущей подписанной сессии; после перезапуска сервера до разблокировки может отображаться русский, затем язык восстанавливается из хранилища.

Некоторые старые динамические сообщения внешних API и сохранённые названия категорий пока могут оставаться на исходном языке. Полный перевод этих сообщений сопровождает перенос соответствующих сценариев.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m coverage run -m unittest discover -s tests -v
python -m coverage report
python -m coverage report --include='wealth_manager/*' --omit='wealth_manager/adapters/web/legacy_routes.py' --fail-under=95
node --check static/app.js
node --test tests/test_frontend.cjs
```

Тесты используют временные зашифрованные файлы и SQLite в памяти. Внешние API не вызываются. Проверяются независимость ядра, сбои записи/снимка, повторное открытие хранилища, пароли, аренда, XIRR, отсутствие двойного дохода, язык, валидация форм и экранирование пользовательских данных. Общий отчёт включает legacy-код; высокий процент нового пакета не означает покрытие всего приложения.

К текущему набору добавлены проверки пассивного импорта, двух независимых экземпляров, конфигурации и миграции по индивидуальным путям, повторного открытия базы, освобождения блокировок при ошибках, запуска/остановки и повторного закрытия runtime, фоновой автоблокировки и повторного сохранения после сбоя.

Общий отчёт включает legacy_routes.py. Порог 95% нового кода исключает только этот перенесённый legacy-модуль; его оставшиеся чтения, настройки и интеграции ещё не переработаны. Browser E2E-прогон не входит в проверку этого этапа: страницы проверяются Flask test client, JavaScript — Node-тестами.

Этап 2 добавляет тесты жизненного цикла операций, идемпотентного расписания, защиты связанных доходов, изменения договора, каскадного удаления, исторической оценки, изоляции пакетных цен, HTTP-валидации и локализации. Сбои диска проверяются сравнением всей базы в памяти и зашифрованного файла до/после операции; отдельный тест проверяет откат платежа и дохода при ошибке снимка.
