# Техническое задание для Codex
## Разработка аналитического дашборда «Экономический цикл РФ» с отраслевыми инвестиционными рекомендациями

### 1. Цель

Разработать в существующем инвестиционном приложении аналитический функционал, позволяющий:

1. Автоматически получать актуальные макроэкономические показатели Российской Федерации из надёжных источников.
2. Анализировать текущую фазу экономического цикла.
3. Формировать краткое аналитическое заключение с объяснением выбранной фазы.
4. Оценивать инвестиционную привлекательность отраслей российской экономики с учётом текущей фазы.
5. Предоставлять возможность перехода от отрасли к списку соответствующих компаний Московской биржи.
6. Использовать существующие карточки компаний и инвестиционные инструменты приложения.
7. Настраивать веса показателей и критерии оценки.
8. Просматривать исторические изменения экономического цикла и инвестиционных оценок.

Результат должен стать частью существующего приложения, а не самостоятельным продуктом.

## 3. Источники данных

Приоритет — официальные источники с возможностью автоматизированной загрузки.

### 3.1. Реальный ВВП

Основной источник:

https://rosstat.gov.ru/statistics/accounts

Дополнительный:

https://www.fedstat.ru/

Получать:

- Реальный ВВП.
- Индекс физического объёма ВВП.
- Рост ВВП год к году (YoY).
- Рост ВВП квартал к кварталу с сезонной корректировкой (QoQ SA).
- Потенциальный ВВП, если имеется методологически сопоставимая оценка.
- Разрыв выпуска (GDP Output Gap), рассчитываемый отдельной аналитической моделью.

Для сравнения абсолютного реального ВВП использовать сопоставимые цены и фиксировать базовый год.

Не смешивать номинальный ВВП, реальный ВВП и индекс физического объёма.

### 3.2. Инфляция

Источники:

https://rosstat.gov.ru/statistics/price

https://www.cbr.ru/

Показатели:

- CPI YoY.
- CPI MoM.
- CPI 3M SAAR.
- Базовая инфляция.
- Инфляционные ожидания населения.
- Инфляционные ожидания предприятий, если доступны.

Сезонно скорректированные показатели использовать из официальных публикаций либо рассчитывать собственной документированной процедурой.

### 3.3. Денежно-кредитная политика

Источник:

https://www.cbr.ru/hd_base/KeyRate/

Получать:

- Текущую ключевую ставку.
- Историю изменений ставки.
- Даты решений Банка России.
- Величину изменения ставки в базисных пунктах.
- Реальную ставку ex ante, рассчитанную с использованием инфляционных ожиданий на сопоставимом горизонте.
- Оценку направленности денежно-кредитных условий.

Изменение номинальной ставки само по себе не должно автоматически означать смягчение или ужесточение условий.

### 3.4. Кривая бескупонной доходности ОФЗ

Источник:

https://www.cbr.ru/hd_base/zcyc_params/

Получать доходности для сроков:

- 1 год.
- 2 года.
- 5 лет.
- 10 лет.

При необходимости использовать дополнительные сроки для построения полной кривой.

Рассчитывать:

`YIELD_SPREAD_10Y_1Y = YIELD_10Y - YIELD_1Y`

`YIELD_SPREAD_10Y_2Y = YIELD_10Y - YIELD_2Y`

Фиксировать изменения спредов за 3, 6 и 12 месяцев.

Определять характер кривой:

- Нормальная.
- Плоская.
- Инвертированная.

Дополнительно выявлять увеличение или сокращение наклона кривой.

Не использовать форму кривой ОФЗ как единственный критерий определения фазы экономического цикла.

### 3.5. Финансовые рынки

Основной источник:

https://www.moex.com/

Использовать официальные рыночные данные Московской биржи и доступные API, включая ISS API.

Показатели:

- IMOEX.
- Индекс полной доходности российских акций.
- RGBI.
- Индекс полной доходности государственных облигаций.
- RUSFAR.
- Доходности и динамика соответствующих инструментов.

Рассчитывать доходности за:

- 1 месяц.
- 3 месяца.
- 6 месяцев.
- 12 месяцев.

Для индексов учитывать особенности расчёта полной доходности и дивиденды.

При отсутствии данных не подставлять фиктивные значения.

### 3.6. Дополнительные индикаторы

Для повышения качества определения фазы экономического цикла предусмотреть:

- Индекс промышленного производства Росстата.
- Уровень безработицы.
- Индикатор бизнес-климата Банка России.
- PMI Manufacturing.
- PMI Services.

PMI использовать только при наличии законного и технически доступного источника.

Недоступность платных показателей не должна препятствовать работе основной модели.

## 4. Исторический период

Предусмотреть хранение исторических данных с максимально доступной глубиной.

Рекомендуемые горизонты:

- С 2003 года — основная база для построения долгосрочных моделей, где доступны сопоставимые ряды.
- С 2015 года — основной период исследования современных фаз российской экономики.
- Последние 5 лет — стандартный горизонт визуального представления.

Для отдельных показателей глубина может отличаться.

Не заполнять пропущенные исторические значения вымышленными данными.

При изменении методологии или базы расчёта обеспечивать сопоставимость рядов.

### 4.1. История публикаций

Сохранять:

- Дату наблюдения.
- Дату публикации.
- Дату получения.
- Источник.
- Версию данных.
- Статус: предварительные / окончательные / пересмотренные.
- Метод расчёта.
- Единицы измерения.
- Сезонную корректировку.
- Базовый год, если применимо.

Желательно поддерживать исторические версии данных (*data vintages*), чтобы результаты прошлых прогнозов и оценок не искажались последующими пересмотрами статистики.

# 5. Аналитическая модель Economic Cycle Engine

Реализовать независимый аналитический модуль, определяющий фазу экономического цикла РФ.

## 5.1. Фазы цикла

Использовать пять стадий:

1. Восстановление — Recovery.
2. Ранняя стадия роста — Early Expansion.
3. Поздняя стадия роста — Late Expansion.
4. Замедление — Slowdown.
5. Рецессия — Recession.

Для каждой стадии должны существовать:

- Уникальный внутренний идентификатор.
- Название RU/EN.
- Описание.
- Набор количественных критериев.
- Набор подтверждающих сигналов.
- Набор противоречащих сигналов.
- Условия перехода между стадиями.

Не определять фазу только по одному показателю или его знаку.

## 5.2. Группы факторов

Основная модель должна анализировать пять групп:

**A. Экономическая активность**

- GDP YoY.
- GDP QoQ SA.
- GDP Output Gap.
- Изменение темпов роста.
- Дополнительные индикаторы производства и деловой активности.

**B. Инфляция**

- CPI YoY.
- CPI 3M SAAR.
- Базовая инфляция.
- Инфляционные ожидания.
- Ускорение или замедление инфляционного давления.

**C. Денежно-кредитная политика**

- Ключевая ставка.
- Динамика ставки.
- Реальная ставка ex ante.
- Направленность денежно-кредитных условий.

**D. Кривая доходности**

- Спред 10Y–1Y.
- Спред 10Y–2Y.
- Динамика спредов.
- Инверсия или нормализация кривой.

**E. Финансовые рынки**

- Динамика индексов акций.
- Динамика рынка облигаций.
- Доходность денежного рынка.
- Относительная привлекательность финансовых активов.

## 5.3. Веса факторов

Настроить начальные веса:

| Группа | Вес |
|---|---:|
| Экономическая активность | 40% |
| Инфляция | 20% |
| Денежно-кредитная политика | 15% |
| Кривая доходности | 15% |
| Финансовые рынки | 10% |

Это стартовая гипотеза, а не подтверждённая статистическая модель.

Все веса должны изменяться через настройки.

Требования:

- Сумма весов должна составлять 100%.
- Предусмотреть нормализацию весов.
- Предусмотреть восстановление значений по умолчанию.
- Сохранять пользовательские настройки.
- Поддерживать дополнительные веса показателей внутри каждой группы.
- Пересчитывать результаты после изменения модели.
- Сохранять версию конфигурации, использованной для каждого расчёта.

## 5.4. Алгоритм классификации

Не использовать примитивное сопоставление вида «низкий рост ВВП = рецессия».

Предложить и реализовать интерпретируемую модель с количественными сигналами.

Она должна учитывать:

- Текущие уровни показателей.
- Направление изменений.
- Ускорение и замедление.
- Устойчивость сигналов.
- Противоречия между показателями.
- Статистическую неопределённость.
- Доступность данных.
- Особенности российской экономики.

Для Output Gap разработать отдельную методику оценки потенциального выпуска. Допускается применение HP-фильтра как одного из вариантов, но необходимо учитывать проблему нестабильности оценок на конце ряда.

Предпочтительно сравнить несколько методик и сохранить возможность их выбора.

Результат классификации должен включать:

- Определённую фазу.
- Оценку уверенности в классификации.
- Значения основных факторов.
- Вклад каждой группы.
- Аргументы в пользу выбранной фазы.
- Противоречащие сигналы.
- Дату расчёта.
- Версию модели.
- Статус полноты данных.

Уверенность не следует представлять как статистическую вероятность, если модель не проходила соответствующую калибровку.

Если данных недостаточно, должна поддерживаться стадия результата `INSUFFICIENT_DATA`, которая не подменяется экономической фазой.

## 5.5. Генерация аналитического заключения

Формировать краткое объяснение на русском и английском языках.

Пример структуры:

**Текущая фаза:** Замедление.

**Заключение:** Рост экономической активности ослабевает. Денежно-кредитные условия остаются ограничительными. Инфляционное давление сохраняется. Совокупность индикаторов соответствует фазе замедления, однако часть сигналов противоречива.

**Подтверждающие факторы:** снижение темпов роста реального ВВП, слабая промышленная динамика.

**Противоречащие факторы:** отсутствие устойчивого сокращения реального ВВП, стабильный рынок труда.

Текст должен формироваться из реально рассчитанных данных.

Запрещено использовать заранее зафиксированное заключение о текущей экономической ситуации.

На первоначальном этапе достаточно шаблонной генерации без обязательного подключения LLM.

# 6. Investment Sector Scoring Engine

Создать независимую модель оценки привлекательности отраслей Московской биржи.

Она должна учитывать текущую фазу экономического цикла, но не ограничиваться только ею.

## 6.1. Отраслевая классификация

Использовать актуальную классификацию отраслей и компаний Московской биржи либо существующую классификацию проекта с документированным сопоставлением.

Примеры:

- Нефть и газ.
- Металлургия и добыча.
- Золотодобыча.
- Электроэнергетика.
- Финансовый сектор.
- Телекоммуникации.
- Информационные технологии.
- Потребительский сектор.
- Продовольственная розница.
- Девелопмент.
- Транспорт.
- Химическая промышленность.

Список является примером и не должен считаться окончательной отраслевой таксономией.

Не смешивать отрасли, подотрасли и тематические инвестиционные группы в одной плоской классификации.

Поддерживать иерархию отраслей и связь эмитентов с несколькими направлениями деятельности при необходимости.

## 6.2. Факторы отраслевой привлекательности

Предусмотреть отдельные группы критериев:

**Макроэкономическая совместимость**

- Соответствие текущей фазе.
- Чувствительность к ключевой ставке.
- Чувствительность к инфляции.
- Чувствительность к валютному курсу.
- Зависимость от экономического роста.
- Зависимость от цен на сырьё.

**Фундаментальные характеристики**

- Выручка.
- Рентабельность.
- Долговая нагрузка.
- Устойчивость денежных потоков.
- Капитальные затраты.
- Дивидендная устойчивость.

**Рыночная оценка**

- P/E.
- EV/EBITDA.
- P/BV, если применим.
- Дивидендная доходность.
- Относительная оценка в сравнении с историей и аналогами.

**Рыночные характеристики**

- Относительная динамика.
- Ликвидность.
- Волатильность.
- Тренд.
- Динамика отраслевого индекса, если доступен.

Метрики должны применяться с учётом специфики отрасли. Например, одинаковая модель оценки не подходит банкам, золотодобывающим предприятиям и электроэнергетике.

## 6.3. Настраиваемые веса

Предусмотреть отдельный набор весов для отраслевого анализа.

Не смешивать их с весами Economic Cycle Engine.

В настройках должны существовать как минимум две независимые модели:

- Economic Cycle Model.
- Sector Attractiveness Model.

В дальнейшем предусмотреть возможность добавления модели оценки отдельных компаний.

## 6.4. Результаты

Для каждой отрасли формировать:

- Итоговый балл привлекательности от 0 до 100.
- Ранг относительно других отраслей.
- Оценку совместимости с текущей фазой.
- Основные драйверы.
- Основные риски.
- Противоречащие сигналы.
- Список ключевых показателей.
- Дату последнего расчёта.
- Полноту данных.
- Объяснение итогового балла.

Оценка 0–100 должна иметь документированную методику нормализации.

Не присваивать высокие оценки отраслям только на основании исторически типичного поведения в конкретной фазе.

Рекомендации должны носить аналитический, а не гарантийный характер.

# 7. Company Explorer — компании Московской биржи

Обеспечить переход от выбранной отрасли к перечню соответствующих компаний.

## 7.1. Источники

Использовать Московскую биржу и уже существующий в проекте справочник компаний.

При отсутствии подходящего механизма реализовать синхронизацию через официальный ISS API.

Не создавать отдельный несвязанный справочник эмитентов.

## 7.2. Информация о компаниях

Для каждой компании по возможности отображать:

- Название.
- Тикер.
- Код инструмента.
- Отрасль.
- Подотрасль.
- Рыночную капитализацию.
- Последнюю доступную цену.
- Изменение цены.
- Ликвидность.
- P/E.
- P/BV.
- EV/EBITDA.
- Net Debt / EBITDA.
- ROE или ROIC при применимости.
- Дивидендную доходность.
- Дату актуальности отчётности.
- Интегральную оценку компании, если она реализована в проекте.

Не использовать одинаковые показатели для всех отраслей без проверки экономического смысла.

Учитывать:

- Несколько классов акций.
- Несколько тикеров одного эмитента.
- Смену тикеров.
- Приостановку торгов.
- Делистинг.
- Отсутствие актуальной отчётности.
- Особенности депозитарных расписок и других инструментов.

## 7.3. Сортировка и фильтры

- Поиск по тикеру или названию.

- Сортировку по фундаментальным показателям.

# 8. Функциональность дашборда

Не фиксировать заранее размещение компонентов.

Финальную композицию интерфейса определить после анализа текущего приложения.

Обеспечить следующие функциональные возможности.

### 8.1. Краткая макроэкономическая сводка

Отображать:

- Текущую фазу экономического цикла.
- Уровень уверенности.
- Краткое аналитическое заключение.
- Дату расчёта.
- Дату последнего обновления данных.
- Важнейшие подтверждающие и противоречащие сигналы.

### 8.2. Ключевые макропоказатели

Предусмотреть компактное представление:

- Рост ВВП.
- Инфляция.
- Ключевая ставка.
- Спред доходности ОФЗ.
- Дополнительные показатели при необходимости.

Для каждого показателя:

- Текущее значение.
- Единица измерения.
- Дата наблюдения.
- Изменение за период.
- Направление тренда.
- Источник данных.
- Переход к подробной истории.

### 8.3. Подробная диагностика цикла

Отображать результаты по пяти группам факторов.

Для каждой группы показывать:

- Текущий сигнал.
- Значения показателей.
- Динамику.
- Вклад в итоговую оценку.
- Использованный вес.
- Объяснение результата.

### 8.4. Исторические графики

Предусмотреть отображение:

- Реального ВВП.
- GDP Output Gap.
- CPI.
- Ключевой ставки.
- Кривой доходности.
- Рыночных индексов.
- Истории изменения экономических фаз.

Поддерживать переключение периодов:

- 1 год.
- 3 года.
- 5 лет.
- 10 лет.
- Максимальная история.

На графике экономического цикла выделять исторические стадии.

При выборе исторической даты отображать доступную на тот момент информацию.

### 8.5. Отраслевые инвестиционные оценки

Выводить рейтинг отраслей.

Обеспечить:

- Отображение отраслевого балла.
- Краткую аргументацию.
- Ключевые риски.
- Переход к подробному анализу отрасли.
- Переход к компаниям выбранной отрасли.

### 8.6. Обновление данных

Предусмотреть:

- Автоматическое обновление.
- Ручную кнопку обновления.
- Индикацию состояния.
- Защиту от параллельного дублирующего обновления.
- Сохранение последней корректной версии данных при ошибке.
- Указание устаревших данных.
- Отображение ошибок загрузки без нарушения работы всей страницы.

Периодичность обновления должна учитывать частоту публикации каждого источника.

Не загружать заново многолетнюю историю при каждом открытии страницы.

# 12. Порядок реализации

Разбей работу на самостоятельные этапы.

**Этап 1. Анализ проекта и проектирование**

Изучи текущую архитектуру, источники данных, модели и интерфейс. Определи, какие компоненты можно переиспользовать. Подготовь план интеграции.

Реализуй загрузку, нормализацию, кэширование, историю и контроль качества данных.

**Этап 3. Economic Cycle Engine**

Реализуй расчёт показателей, определение стадии цикла, объяснение и историю классификации.

**Этап 4. Макроэкономический дашборд**

Интегрируй сводку, показатели, графики, диагностику и настройки модели в существующий UI.

**Этап 5. Sector Scoring Engine**

Реализуй отраслевую классификацию, модель привлекательности и рейтинг отраслей.

**Этап 6. Company Explorer**

Интегрируй отраслевой рейтинг со справочником эмитентов и существующими карточками компаний.

**Этап 7. Проверка и оптимизация**

Проведи тестирование, историческую проверку модели, оптимизацию запросов и устранение проблем интерфейса.

Каждый этап должен иметь завершённый результат и тесты.

После завершения этапа предоставляй краткую сводку:

- Какие файлы изменены.
- Какие тесты выполнены и каковы результаты.
- Какие источники данных работают.
- Что осталось.
- Какие ограничения обнаружены.

**Не переходи к следующему этапу без моего явного подтверждения.**

# 13. Критерии готовности

Функциональность можно считать завершённой, если:

- Данные загружаются из подтверждённых источников.
- Для каждого показателя отображается актуальность и источник.
- Экономическая фаза рассчитывается алгоритмически.
- Пользователь может объяснить результат по отдельным факторам.
- Веса настраиваются и сохраняются.
- Исторические данные можно анализировать.
- Отрасли ранжируются с учётом макроэкономической ситуации и других факторов.
- Отраслевые оценки имеют объяснение.
- Можно открыть компании выбранной отрасли.
- Существующие карточки компаний используются повторно.
- Обработка ошибок не приводит к потере ранее полученных данных.
- Интерфейс соответствует текущему дизайну приложения.
- Функциональность покрыта необходимыми тестами.
- Не нарушены существующие бизнес-процессы приложения.

## 14. Важные ограничения

Не использовать искусственные данные в рабочих расчётах.

Не подменять отсутствующие показатели произвольными значениями.

Не считать историческую доходность активов гарантией будущей.

Не превращать инвестиционную привлекательность отраслей в безусловную рекомендацию к покупке конкретных акций.

Не усложнять архитектуру без необходимости.

Не создавать самостоятельный UI, если функциональность можно интегрировать в текущие компоненты.

Не изменять существующую бизнес-логику, не связанную с поставленной задачей, без необходимости.
