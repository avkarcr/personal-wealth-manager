# Аудит и оптимизация тестов

27.11.2026, ветка `feature/macro-dashboard-automation`. Исходная ревизия `c2f55a4` содержала все результаты М1–М12. Исходный набор проходил, в том числе в [GitHub Actions](https://github.com/avkarcr/personal-wealth-manager/actions/runs/45970017273). При аудите проверены назначение сценариев, условия, при которых их утверждения могут ошибочно пройти, изоляция данных, покрытие строк и ветвей, стоимость подготовки и интеграционные границы.

## Какие ошибки обнаружили тесты

| Дефект | Как воспроизведён | Результат исправления |
|---|---|---|
| После отказа записи при смене пароля открытое хранилище принимало новый пароль, а основной файл открывался старым | Прерван `os.replace` во время смены пароля. Сверены байты исходного файла, оба пароля и токен открытой сессии. Через HTTP ошибка записи также прерывала запрос | Новый ключ и токен вступают в силу после атомарной замены основного файла. При отказе синхронизации, удаления старой копии или замены сохраняются прежний пароль, сессия и ожидающие записи. Через настройки можно повторить операцию. После успеха старый токен лишается доступа, скачанная копия открывается новым паролем и содержит исходную запись |
| В английском отчёте по недвижимости оставалась подпись «Расходы» | Ключ передавался из списка в Jinja. Проверка прямых вызовов перевода и проверка HTTP 200 обе проходили. При проверке текста карточки воспроизведён дефект | В словарь добавлен ключ `Расходы`. В HTTP и Chromium проверяются русская подпись и английская `Expenses`. Статическая проверка читает и строковые константы, переданные в выражения шаблона |

Во время смены пароля прежняя локальная `.bak` удаляется непосредственно перед заменой основного файла. Если откажет последняя операция, основное хранилище по-прежнему открывается прежним паролем, но локальная `.bak` может уже отсутствовать. Самостоятельно скачанные ранее копии сохраняют свой пароль. [Реализация сохранения](../vault.py) · [Проверки отказов](../tests/test_vault.py) · [Восстановление скачанной копии](../tests/test_factory.py)

## Какие проверки усилились

- **Импорт.** Для обоих форматов проверяются допустимые 500 и отклоняемые 501 строка. Некорректные строки передаются с заголовком своего формата. Для счёта с выключенным журналом проверяются номер проблемной строки и состояние БД. Для полной сверки ожидаются идентификаторы и статусы обеих позиций. После отказа записи хранилище открывается повторно, подтверждается тот же предварительный просмотр и проверяются точные остатки после повтора. [Тесты импорта](../tests/test_importing.py)
- **Финансовый результат.** При неизвестном курсе пополнения известная стоимость имущества сохраняется, прибыль и XIRR отсутствуют. При известном курсе тот же пример даёт прибыль 500 и годовую доходность 50%. В JavaScript проверен успешный ответ ЦБ на дату платежа арендатора и результат −0,50 ₽. [Отчёты](../tests/test_reporting.py) · [Клиентский расчёт](../tests/test_frontend.cjs)
- **Миграции.** Добавлен путь от синтетической старой схемы без необязательных столбцов до версии 21. Проверены ID счёта и поступления, ссылка между ними, сумма, валюта, заметка, значения новых полей и внешние ключи. У исторических схем v8–v20 тесты задают исходную версию явно и затем вызывают штатное обновление. Сохранились проверки отката, повторного открытия и SQL-dump для Python 3.9. [Миграции](../tests/test_entity_migration.py) · [Подготовка версий](../tests/vault_fixtures.py)
- **Границы записи.** Для невалидного счёта проверяется, что фабрика транзакции не вызывалась. Прежде пустой список изменений допускал вход в транзакцию. Проверки проводок, диска и повторного открытия проверяют различные последствия отказа и сохранены отдельно. [Граница транзакции](../tests/test_hexagonal.py)

Две искусственные ошибки проверены на отдельных временных копиях кода. Снижение лимита CSV до 499 не обнаруживалось прежним граничным тестом. Возврат пустого списка при полном совпадении остатков проходил прежнюю проверку через `all()`. Усиленный тест в каждом случае завершился ошибкой. Сравнение относится к указанным двум регрессиям.

## Что ускорено и какие гарантии сохранены

- Профилирование `test_macro_data` и `test_ledger` до изменений показало 24 вызова scrypt за 2,11 с и 11 созданий приложения за 0,86 с. Общая подготовка бизнес-сценариев создаёт отдельные каталог, базу, соль и зашифрованный файл для каждого теста. Только для этих временных файлов параметр scrypt N снижен с 32768 до 1024. AES-GCM, синхронизация, атомарная запись и открытие работают обычным путём. Проверки хранилища, первого запуска и ручное измерение оставлены со штатным N. Параметры в заголовке файла также проверяются тестом.
- Flask-приложение и клиент создаются при обращении из теста. Проверки статического текста и границ импортов выполняются без базы. Четыре пересекающихся обхода переводов заменены двумя проверками деревьев Python и Jinja с указанием проблемного файла. Локализованные формы, сообщения и пользовательские данные дополнительно проверяются в HTTP.
- Пять вариантов изменения KPI проверяются на разных карточках одного ответа. Сохранены обе локали, ноль, оба знака, оба крайних значения и исходная точность. На язык приходится два рендера вместо пяти. Для интервалов 3, 5 и 10 лет добавлена точная проверка начальной даты. Интервалы один год и вся история проверяются на расчёте разрыва ВВП.
- Для двух больших multipart-запросов тест закрывает временные потоки Werkzeug. Устранены два воспроизводившихся предупреждения о незакрытых файлах. Node 22 и проверки синтаксиса выполняются один раз в отдельной задаче CI. Обе версии Python сохраняют самостоятельные прогоны с покрытием.

## Измерения и пределы проверки

Два последовательных полных прогона до и два после изменений выполнены на Linux с Python 3.12.14, включённым branch coverage и одинаковой командой discovery. Время взято из отчёта `unittest`. В медиану не входят установка зависимостей, Node и браузер.

| Показатель | Исходная ревизия | После аудита |
|---|---:|---:|
| Python, найдено и прошло | 399 | 402 |
| Два прогона Python, с | 74,580 и 68,794 | 46,655 и 46,931 |
| Медиана Python, с | 71,687 | 46,793 |
| Выполненные строки | 7304 / 7407 | 7338 / 7419 |
| Выполненные исходы ветвлений | 2155 / 2300 | 2167 / 2300 |
| Общее покрытие строк и ветвлений | 97,45% | 97,80% |
| Покрытие пакета в области порога CI | 98,53% | 98,57% |
| Node / Chromium | 17 / 3 | 18 / 4 |

Локальная медиана Python сократилась на 34,7%. Время CI зависит также от очереди и установки зависимостей. Все 402 теста прошли и в перемешанном порядке с `random.Random(20261127)`. Перехват подключений и DNS-запросов в процессе тестов зафиксировал ноль попыток обратиться к внешнему узлу.

Ручной Linux-бенчмарк М12 заново выполнил обработку 18 458 ревизий, сохранение четырёх снимков и открытие зашифрованного файла. Для каждого из графиков акций и фаз зарегистрировано одно полное чтение ревизий. Проверка использовала штатные параметры scrypt.

Покрытие включает ветвления. Порог 95% применяется к `wealth_manager` за исключением `legacy_routes.py`. Показатели общего отчёта включают этот файл и корневые модули. Среди оставшихся пробелов есть совместимые обёртки `calc.py`, отдельные внутренние ветви отката миграций и некоторые настройки старого HTTP-адаптера. Каждая поддерживаемая платформа и каждый способ отказа диска требуют отдельных проверок.

Автоматические сценарии используют локальные данные. При проверке М12 воспроизводятся архивные срезы ALFRED и ЦБ. Текущая доступность внешних API, нативные выписки брокеров и прогнозная сила моделей остаются за пределами этого результата. [Исторические данные и методика М12](macro-automation/M12-historical-validation.md)

Команды обычного прогона приведены в [AGENTS.md](../AGENTS.md). Для измерения длительности отдельных тестов на Python 3.12 к `unittest discover -s tests -v` добавлен `--durations 0`. Ручной нагрузочный сценарий запускается командой `PYTHONPATH=tests:. python tests/benchmark_macro_history.py`.
