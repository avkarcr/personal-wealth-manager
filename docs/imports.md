# Импорт и сверка — этап 5

Путь: **Операции → Журнал сделок и остатков → Импорт и сверка**. Интерфейс RU/EN.

## Поддерживаемый формат

Реализован единый CSV v1 для подготовленных данных брокеров и криптобирж. Фирменные XLSX/PDF/CSV, API и автоматическое распознавание форматов пока не поддерживаются. Для конкретных адаптеров нужны обезличенные образцы выписок. Они могут реализовать порт `StatementParser`, сохранив общую проверку и проведение.

Файл: UTF-8 (BOM допустим), разделитель `,` либо `;`, точка в числах без разделителей тысяч, дата `YYYY-MM-DD`. Не более 1 МБ и 500 записей. Заголовки обязательны в указанном порядке. Кавычки и переводы строк внутри CSV-полей поддерживаются.

Шаблоны скачиваются на странице. Там же показаны ID позиций, счёт, тикер и валюта. Используйте ID этого хранилища: совпадение названия или тикера не служит автоматическим сопоставлением.

## Операции

```csv
external_id,date,kind,holding_id,currency,quantity,price,fee,cash_id,target_id,note
funding-001,2026-11-15,deposit,2,RUB,1000,0,0,,,Пополнение
trade-001,2026-11-15,buy,1,RUB,2,100,1,2,,Покупка
```

ID 1 и 2 в примере условные; замените их на собственные. Включите журнал на счёте после сверки входящих остатков. Новые позиции сначала создайте с количеством 0. Импорт не создаёт счета и активы автоматически.

| Поле | Значение |
|---|---|
| external_id | Постоянный уникальный ID операции из выписки, до 100 символов |
| date | Дата не раньше включения журнала и не позже сегодня |
| kind | buy, sell, deposit, withdrawal, income, expense, transfer |
| holding_id | ID актива сделки, источника перевода или денег для денежных операций |
| currency | Валюта позиции и цены; проверяется против справочника |
| quantity | Положительное количество или сумма |
| price | Цена сделки или оценка перевода актива; для денежных операций не используется |
| fee | Неотрицательная комиссия; пустое значение означает 0 |
| cash_id | Деньги для сделки/комиссии в том же счёте и валюте |
| target_id | Позиция получателя перевода в другом счёте с журналом |
| note | Заметка; итоговая заметка вместе с источником и external_id ограничена 2000 символами |

Комиссии включаются в строку сделки, а не повторяются отдельным расходом. Внутренний перевод задаётся одной строкой transfer: второй денежный поток создаётся автоматически. Применяются ограничения журнала: длинные позиции, без межвалютной конвертации. Для актива нужны одинаковые тикер, класс и валюта получателя.

1. Выберите счёт, укажите постоянное имя источника (например, «Брокер: основной договор»), загрузите CSV.
2. Предпросмотр проверит **весь** файл и покажет новые и существующие операции, суммы, комиссии, получателей. Сортировка по дате, внутри даты — исходный порядок строк; относительно ранее проведённых операций той же даты новые строки идут после них.
3. Подтвердите. Все строки, остатки и денежные потоки сохраняются одной транзакцией. Ошибка проверки или записи зашифрованного файла отменяет весь импорт.

Предпросмотр не сохраняет записи и не изменяет зашифрованный файл. Подписанное подтверждение действует 30 минут, привязано к текущей разблокировке хранилища и проверенной версии данных. После изменений или повторного открытия нужно загрузить файл заново.

Повторы определяются по сочетанию **счёт + имя источника + external_id**, независимо от имени файла. Уже проведённая строка пропускается, изменённые данные того же ID блокируют файл. Повтор ID внутри файла считается ошибкой. Отменённая операция повторно не активируется — исправьте её отдельно в журнале. Имя источника чувствительно к регистру; изменение источника создаёт другую область ID.

Ручные операции без внешнего ID не сопоставляются автоматически. При переносе выписки проверьте, не введены ли эти операции ранее вручную. Не загружайте историю, уже включённую во входящие остатки. Исходный файл отдельно не архивируется; источник и внешний ID сохраняются в заметке записи журнала.

## Сверка остатков

```csv
holding_id,currency,quantity
1,RUB,2
2,RUB,799
```

Выберите счёт и дату остатков на конец дня. Нужен полный список, включая нулевые остатки. Одна строка на позицию; неизвестные ID, другая валюта, повтор ID и отрицательные количества отклоняются.

Сверка восстанавливает количество из входящих остатков и действующих операций до указанной даты включительно. Сравнение выполняется точно в Decimal, без округления и допуска. Отчёт показывает количество в журнале и выписке, разницу **журнал минус выписка** и статус:

- «Совпадает» — количества равны;
- «Расхождение» — количества различаются;
- «Нет в выписке» — строка отсутствует, это не нулевой остаток.

Это сверка количеств, включая деньги, а не рыночной стоимости, налоговой базы или себестоимости. Для даты до включения журнала результат не строится. Отчёт ничего не исправляет и отдельно не сохраняется; исправления проводятся через журнал. Отменённые записи исключаются как исправленные ошибки, в том числе при сверке прошлой даты.

## Архитектура и проверки

`modules/importing` содержит правила идентичности, предварительную проверку, атомарное проведение и сверку; CSV и Flask — внешние адаптеры. Импорт использует тот же путь проведения, что и ручной журнал. Изменение схемы БД не требуется.

Тестируются повторные и пересекающиеся выписки, конфликт ID, отменённые записи, нехватка средств, откат памяти и диска, устаревшее подтверждение, срок действия и привязка к хранилищу, точные дроби, сверка прошлой даты, повреждённые файлы, ограничения размера, RU/EN и экранирование заметок.
