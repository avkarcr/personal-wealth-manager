# М6 — производные показатели и Output Gap

Реализован в `feature/macro-dashboard-automation`. По решению пользователя от 22.11.2026 Росстат не заменяется: выбор альтернативного поставщика отложен до опыта эксплуатации. Открытый пункт М4 сохраняется. Новые расчёты используют уже загруженные ряды, включая подтверждённый ручной импорт, и не обращаются к внешним источникам.

## Доступ в приложении

«Макроэкономика → Производные показатели» (также ссылка из «Ряды данных»). Пользователь выбирает конкретный ряд/источник, при необходимости второй ряд, историческую дату, режим известных/последних версий, метод Output Gap и окно 20–120 кварталов. GET выполняет предпросмотр без записи. POST сохраняет результат, конфигурацию, версию алгоритма `macro-derived-v1`, выбранные revision_id и происхождение каждого рассчитанного значения. Сохранённый расчёт можно открыть после обновления исходных данных. Интерфейс RU/EN, отображение округлено до 4 знаков; сохранённые значения не округляются до точности экрана.

При отсутствии подходящих данных показываются причины и частичный результат. Показатели из разных источников, базовых лет, методик и режимов SA/NSA не склеиваются. Старые ручные записи без паспорта остаются доступны в прежнем интерфейсе, но не получают выдуманную частоту и сезонность ради расчёта.

## Формулы версии 1

Все доли переводятся из процентов явно, scale применяется к исходному значению. Расчёты выполняются Decimal с 50 значащими цифрами, ROUND_HALF_EVEN. Индекс «предыдущий/сравниваемый период = 100» нормализуется как `index * scale - 100`; процент роста сохраняется как процент. Ноль — допустимый результат, отсутствие результата хранится отдельно.

| Показатель | Формула / политика |
|---|---|
| Реальный ВВП YoY | `100 * (Y[t] / Y[t-4] - 1)` для кварталов, лаг 1 для лет. Нужна непрерывная последовательность периодов |
| GDP QoQ SA | `100 * (Y[t] / Y[t-1] - 1)`, только квартальный реальный ряд SA |
| Ускорение | Разность соседних темпов роста в п.п. Для GDP — изменение YoY между соседними периодами; для CPI — изменение выбранного MoM или YoY |
| CPI YoY из MoM | `100 * (product(1 + mom[t-i]/100, i=0..11) - 1)`, ровно 12 последовательных месяцев |
| CPI 3M SAAR | `100 * (product(1 + mom_sa[t-i]/100, i=0..2)^4 - 1)`, только 3 последовательных месяца SA |
| Изменение ставки | `100 * (rate[t] - rate[previous])`, базисные пункты; разрыв между доступными датами максимум 7 дней. Это наблюдаемое изменение, а не восстановленная дата решения ЦБ |
| Спред ОФЗ | 10 лет минус 1 год или 2 года, одна дата, страна, источник и методика; п.п. |
| Форма кривой | Спред > 0.10 п.п. — normal; < -0.10 — inverted; иначе flat. Порог 0.10 — прозрачное правило версии 1, не эмпирически откалиброванный классификатор цикла |
| Изменение спреда | Разность текущего спреда и значения 3/6/12 календарных месяцев назад; п.п. Знак показывает увеличение/сокращение наклона |
| Доходность индекса | `100 * (index[t] / index[anchor] - 1)`, горизонты 1/3/6/12 календарных месяцев. IMOEX/RGBI — ценовая, MCFTR/RGBITR — полная доходность соответствующего индекса |
| Реальная ставка ex ante | Точная формула Фишера: `100 * ((1 + nominal/100) / (1 + expected_12m/100) - 1)`. 1-летняя доходность ОФЗ либо ключевая ставка с явно подтверждённым допущением её неизменности 12 месяцев |

Для рыночных горизонтов anchor — последняя доступная дата не позже календарной даты сравнения, максимум 7 дней назад. Данные после anchor не используются. Сохраняются идентификаторы обеих точек; фактический срок может отличаться на несколько дней из-за календаря. Это доходность индекса, без пользовательских комиссий/налогов, не annualized return.

Для ex ante датой результата является as_of, а не более ранняя дата ставки. Используется последняя доступная пара на дату расчёта: номинальная ставка не старше 7 дней, месячные ожидания не старше 45 дней. Горизонт ожиданий строго 12 месяцев; код `inflation_expectations_12m` не означает фактический CPI YoY. Возраст ожиданий и различие их даты со ставкой остаются приближением: это условная текущая оценка, а не точная реализованная доходность или восстановленная история ожиданий. Месячные ожидания формируются как отдельный паспорт; допускаются отрицательные ожидаемые темпы выше -100%.

Для ручного импорта добавлены паспорта CPI MoM SA (индекс/процент) и инфляционных ожиданий на следующие 12 месяцев. Это возможность загрузить подтверждённый подготовленный ряд, не подключение нового поставщика. Приложение не объявляет NSA сезонно скорректированным и не выполняет скрытую сезонную очистку.

## Output Gap: две диагностические модели

Вход: положительный квартальный уровень реального ВВП в постоянных рублях, SA, известный базовый год, одна методика. Номинальный ВВП, индекс роста, годовой или NSA-ряд для модели не подходят.

Для каждого квартала берётся только окно, заканчивающееся этим кварталом, максимум 40 кварталов по умолчанию. Минимум — 20 непрерывных кварталов. Это инженерное ограничение качества версии 1, а не гарантия статистической точности. После разрыва история окна набирается заново; значения не интерполируются. Масштаб приводится к рублям до логарифмирования.

1. **HP в логарифмах, λ=1600.** Решается задача минимизации `sum((log(Y)-trend)^2) + lambda * sum(second_difference(trend)^2)`. Бандовый LDL' solver, линейная сложность по длине окна. Для каждого периода берётся только последний элемент решения соответствующего окна; полный двусторонний фильтр на будущей истории не подставляется в старые точки.
2. **Логлинейный тренд.** OLS `log(Y)=a+b*t` на том же прошлом окне; значение тренда на конце окна. Метод служит прозрачной альтернативой, предполагает постоянный трендовый темп роста внутри окна.

`potential_proxy = exp(trend)`; `gap = 100 * (Y / potential_proxy - 1)`.

Оба метода оценивают статистический тренд, а не официально измеренный потенциальный выпуск. Дополнительно сохраняется разница `gap_HP - gap_loglinear` в п.п. — чувствительность к выбору метода, **не** доверительный интервал и не вероятность. Структурный сдвиг и шок могут изменить сам тренд и исказить трактовку разрыва. Вывод о фазе цикла относится к М7, историческая калибровка и проверка — к М12.

Методологические источники:

- [statsmodels 0.14.3: HP filter](https://www.statsmodels.org/v0.14.3/generated/statsmodels.tsa.filters.hp_filter.hpfilter.html): функция потерь, линейная система и λ=1600 для кварталов. Зависимость statsmodels не добавляется; реализация использует Decimal и проверяется независимым рациональным решением малой системы.
- [IMF, How Informative Are Real Time Output Gap Estimates in Europe? (2019)](https://www.elibrary.imf.org/view/journals/001/2019/200/article-A001-en.xml): проблема конечных точек и пересмотров оценок. Полный текст при веб-проверке недоступен (403); это дополнительная библиографическая ссылка, не заявленная численная верификация модели.

## Исторический режим и воспроизводимость

Режим known сначала отбирает ревизии, доступные на as_of. Неизвестная публикация означает доступность с момента получения. Затем исключаются наблюдения с периодом после выбранной даты. Для каждой точки модели используются только периоды до этой точки. Добавление будущего квартала не меняет предыдущие оценки при неизменных входных ревизиях и настройках.

Все точки одного расчёта используют винтаж, выбранный на **одну** as_of. Это не последовательность реальных прогнозов, сделанных в даты каждой точки: для такого backtest нужно отдельно вызывать расчёт на соответствующих исторических as_of. Режим latest допускает поздние пересмотры и явно маркируется. Неизвестные публикации, пересмотры, пропуски и устаревшие данные показываются отдельно. Предупреждение о давности: daily >7, monthly >75, quarterly >200, annual >550 дней от конца периода до as_of; это контрольные пороги версии 1.

Каждая числовая точка хранит точные использованные revision_id. Снимок расчёта также хранит все выбранные входные ревизии (включая необходимые для диагностик), паспорт рядов и параметры. Повторное сохранение идентичного результата возвращает прежний ID. Сохранение из UI проверяет fingerprint предпросмотра; изменение данных во время вычисления проверяется revision token перед commit. При lock/unlock проверяется поколение vault. Ошибка диска откатывает расчёт вместе со связями на входные версии.

## Архитектура и схема

- `modules/macroeconomics/derived.py`: чистые функции без Flask/SQLite/HTTP.
- `modules/macroeconomics/calculations.py`: сценарии preview/save и версия результата.
- Порты CalculationSession / CalculationRepository; адаптеры Session и `persistence/macro_calculations.py`.
- HTTP/Jinja: выбор, результат, диагностика, сохранённые расчёты; графический аналитический дашборд остаётся М8.
- Схема 17: immutable `macro_calculations`, связи `macro_calculation_inputs` с FK на source revisions. Полный rollback миграции через существующий init_db; новые и старые vault поддерживаются. Исходные наблюдения не изменяются. Конфигурация встроена в неизменяемый расчёт; управление версиями весов модели цикла относится к М7.
- До 10000 выбранных наблюдений на расчёт, модельное окно до 120 кварталов; интерфейс показывает последние 12 точек каждой метрики и 20 сохранённых расчётов. Старые результаты остаются в БД. Хранение множества больших снимков увеличивает размер vault; автоматической очистки нет.

Проверки: математические эталоны, compounding, единицы/масштаб, високосные даты, доступность anchor, пропуски, короткие/неподходящие ряды, сохранение нуля, сравнение методов, отсутствие будущих периодов и поздних ревизий в known, происхождение, snapshot после пересмотра, атомарность и шифрованное восстановление, миграция, RU/EN и HTTP.
