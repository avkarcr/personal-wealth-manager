# М5 — рыночные ряды и обновление

Реализован в `feature/macro-dashboard-automation`. М6 не начинается автоматически.

## Проверенный источник и семантика

Ограниченная live-проверка 22.11.2026: публичный MOEX ISS, история 09–12.01.2024, HTTP 200 для пяти рядов. Исходные JSON сохранены в `tests/fixtures/moex/`; CI работает без сети. URL каждого запроса сохраняется с исходным JSON и версией парсера `moex-iss-v1` в зашифрованном vault.

| Ряд | Что хранится | BOARDID / TRADINGSESSION | Единицы |
|---|---|---|---|
| IMOEX | Ценовой индекс акций | SNDX / 3 | пункты индекса |
| MCFTR | Полная доходность акций, брутто | RTSI / 3 | пункты индекса |
| RGBI | Ценовой индекс гособлигаций | SNDX / 3 | пункты индекса |
| RGBITR | Полная доходность гособлигаций | SNDX / 3 | пункты индекса |
| RUSFAR | Ставка денежного рынка | MMIX / 3 | проценты |

Берётся CLOSE. Ценовой индекс не подменяет полную доходность. Дата торгов — дата наблюдения, не публикации; публикация остаётся unknown. Строгий исторический as-of использует момент получения, когда дата публикации неизвестна. Пропущенный CLOSE не становится нулём; календарные выходные не дополняются искусственными значениями. Производные доходности относятся к М6.

Фиксированный endpoint: `https://iss.moex.com/iss/history/engines/stock/markets/index/securities/{CODE}.json`. Проверяются SECID, даты, board/session, Decimal, уникальность дат, полнота страниц и стабильность TOTAL. До 90 календарных дней на запрос, 4 страницы/400 строк, 2 МБ на страницу, timeout 15 секунд; redirect запрещён. Лимит 1990 для начала пользовательского диапазона — защитная граница, а не обещание наличия истории с этого года.

[Условия MOEX ISS](https://www.moex.com/a2193): доступ без договора предназначен для ознакомления; иное использование требует соответствующего договора. Поэтому MOEX по умолчанию выключен. В настройках пользователь выбирает «Ознакомление» или «Есть соответствующий договор». Выбор не оформляет и не проверяет договор. Режим общий для пяти рыночных рядов и фиксируется в журнале запуска. API-ключи и платные подписки приложение не приобретает.

## Настройки и расписание

Ссылка «Обновление макроданных» доступна в настройках и макроэкономике. RU/EN: выбор источника, начало истории, интервал 1–168 часов, включение/выключение расписания, режим MOEX, ручная загрузка и журнал последних 100 запусков. По умолчанию все расписания выключены. Поддерживаются проверенные адаптеры ЦБ (ставка/ОФЗ) и пять рыночных рядов. Автоматический Росстат остаётся открытым ограничением М4 и в список не включён.

Worker запускается явно вместе с ApplicationRuntime, отдельно от автоблокировки. Он работает только при запущенном приложении и разблокированном неистёкшем vault. Никакого фонового хранения пароля или внешнего cron. Фоновая работа не продлевает пользовательскую сессию. Закрытие останавливает worker, ждёт завершения ограниченного сетевого запроса и отбрасывает незавершённую загрузку перед блокировкой vault.

За один проход обрабатывается один источник, не более 90 дней, до вчерашней даты UTC. При отставании следующая порция назначается через минуту, при достижении вчерашней даты — через выбранный интервал. Повторно проверяются последние 7 календарных дней. Это окно не гарантирует обнаружение более старых пересмотров: их можно проверить ручной загрузкой. Отключение не стирает checkpoint; изменение начала истории сбрасывает его. Часы и даты журнала/расписания — UTC.

Ручной POST сохраняет существующий синхронный сценарий М3 (до 366 дней для ЦБ, 90 дней для MOEX), освобождает vault lock на время сети. Автоматические загрузки выполняются worker. Короткий асинхронный ручной POST из первоначального дизайна пока не реализован; долгий ручной запрос может ждать источник в браузере. GET не изменяет данные и не запускает загрузку. Ручной диапазон не продвигает автоматический checkpoint, чтобы не пропустить промежутки истории.

## Надёжность и границы

Политика расписания находится в application-модуле `modules/macroeconomics/scheduling.py`; HTTP и JSON — в адаптерах; состояния расписания/журнала — в persistence. Потоки принадлежат runtime. Схема 16 не меняется: используется ограниченный JSON версии 1 в `settings.macro_refresh_v1`, внутри зашифрованного vault.

Перед сетью сохраняется running. Только после проверки всех страниц одним UnitOfWork сохраняются данные, checkpoint и итог журнала. Валидный пустой ответ помечается empty и продвигает checkpoint; это не утверждение о нулевых значениях. Ошибка не продвигает checkpoint и не удаляет прошлые данные. Retry через 5, 10, 20… минут, максимум 6 часов; сетевые HTTP-ошибки обрабатываются общей политикой, Retry-After отдельно пока не учитывается. Тексты исключений с приватными подробностями в журнал не попадают.

Один gate не допускает параллельных ручных и автоматических запусков в процессе. После сети проверяются поколение vault, idle timeout, отмена, версия настроек и режим доступа. Ответ после lock/unlock или изменения настроек отбрасывается. При сбое диска откатываются и данные, и checkpoint. Если сохранить итог невозможно, durable running остаётся до следующего запуска: тогда он помечается interrupted. Нельзя запускать несколько процессов над одним vault — существующее однопроцессное ограничение приложения сохраняется.

## Проверки

Контракты пяти реальных ISS fixtures; пагинация и неполные ответы; пустые дни и пропуски; неверные значения/идентичность; неизменность manual/checkpoint; catch-up, overlap и backoff; запрет доступа; изменение настроек в полёте; отмена, lock/unlock, shutdown; отказ диска; зашифрованное восстановление; отсутствие блокировки автоблокировки сетевым запросом; запуск потоков и очистка при ошибке; RU/EN и формы. Полный набор Python и Node выполняется перед коммитом и в CI Python 3.9/3.12.
